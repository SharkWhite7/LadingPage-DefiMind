The x402 standard

Your agent pays per request. You still set the rules.

x402 is an open standard that brings HTTP 402 Payment Required back to life: an API answers with its price instead of the data, the caller pays in stablecoin, and the request goes through. No account, no invoice, no monthly plan — just the request and the fraction of a cent it costs.

402

The API names its price

Your agent asks for something and gets back a payment requirement instead: how much, in which token, to whom.

DFM

DeFiMind decides

It reads the terms, checks them against your limits and allowlists, and rehearses the payment against the real chain. Anything off and the answer is no — your agent never sees a key either way.

Why it matters now: agents are starting to buy things one call at a time — data, inference, compute. x402 is how they pay for it, and DeFiMind is the part that decides whether they should.

The problem

An agent that can spend is an agent that can be drained.

The moment an agent can pay, one bad instruction — a prompt injection, a bug, a leaked key — empties a wallet in seconds. And an agent is a far easier thing to talk into a mistake than a person is.

Handing an agent a private key trades all of your funds for a little convenience. DeFiMind removes that trade-off: the agent gets spending power, you keep the keys, and there is a hard ceiling on what can go wrong.

How it works

Check it, test-run it, then sign it. Or reject it.

Every payment takes the same four steps, in the same order. No exceptions, no fast path, no override.

01

Request

The agent asks

It asks DeFiMind to pay, through an MCP tool or the HTTP API. It holds no keys and no money, so asking is the only thing it can do. The request is written down before anything else happens.

02

Policy

Your rules decide

The payment is checked against the limits you set for this agent, and only against those. Any doubt is a rejection, never a guess.

per-payment limitdaily limitallowed chains allowed tokensallowed recipientsallowed domains
03

Test run

Rehearsed before signing

The exact transaction is simulated against the real chain to see what it would actually do — not what the agent says it does. If the effect and the intent do not match, there is never a signature.

balance changeshidden permissionsunknown programsauthority changes
04

Decide

One of three outcomes

Under your threshold it is approved and paid. At or above it, it stops and waits for you on Telegram. Breaking a rule or failing the test run, it is rejected outright. Whichever it is, the decision and the reason go into the audit log.

The rule that matters: text the agent provides — its stated reason, the URL, an API response — is shown to you, but is never used to make a decision. Decisions use only your policy and the simulated effect. An agent that lies about what it is doing changes nothing.

Policy engine

A new agent starts at deny-all — it can spend nothing until you allow it. Limits, allowlists and the approval threshold are yours to set, and only yours to change.

Pre-sign test run

The transaction is rehearsed against the real chain before a signature exists. Balance changes, permission grants and unknown programs all come out in the rehearsal, where they are harmless.

Telegram approvals

Anything at or above your threshold waits for you, with a plain summary of what the transaction will actually do. No answer within ten minutes and nothing is paid.

Kill switch

One command pauses every agent at once and prepares, for each chain, the transaction that sets the spend limit to zero. You sign it and the vault is sealed.

Onchain cap

Built on an already-audited, already-deployed primitive — the Squads Spending Limit and the Safe Allowance Module. We deploy no contracts of our own, so there is nothing new for you to trust.

Audit log

Every request, every decision and the reason behind it. Approved, asked or rejected — all of it written down and readable afterwards, in order.

Human approval

The big ones wait for you.

You set the threshold. Anything at or above it stops and asks, with a summary written in plain language — not the agent's explanation of itself, but what the transaction would actually do on the chain.

  • An approval is redeemed once, for exactly that chain, token, amount, recipient and domain
  • It expires after ten minutes, so silence means nothing is paid
  • Every message is cryptographically signed; replayed or stale events are refused
  • One command pauses every agent at once, on every chain
  • The default answer, in every ambiguous case, is no

FAQ

The questions that matter.

Is it live yet?

No. The core is built and tested, but it is not open to the public and nobody is running real money through it. Solana is the first chain we are launching on, and this page will say so the moment the first policy can go live — not before.

What is x402, exactly?

An open standard that lets a website or API charge a small fee per request. The server answers 402 Payment Required with its terms, the caller pays in stablecoin, and the request is retried with proof of payment. DeFiMind sits in the middle of that loop: it reads the terms, checks them against your rules, test-runs the payment, pays only if it passes, and hands the result back to your agent.

Why Solana first?

Sub-second settlement and fees small enough that paying a fraction of a cent per API call actually makes sense — which is the whole point of x402. It also has Squads v4, an audited multisig with a spend limit the chain itself enforces, so we do not have to deploy a contract of our own.

Can my agent ever touch the funds in my multisig?

No. The agent never holds a key. DeFiMind holds the key of a small spending wallet, and your vault refills it through a blockchain-enforced limit that can never exceed your daily cap.

What if DeFiMind itself is compromised?

The cap still holds, because the blockchain enforces it rather than our software. The most that can be taken in a day is your cap plus whatever sits in the spending wallet. The kill switch shuts it off entirely once you sign.

Do you deploy your own smart contracts?

No. We use audited, already-deployed vault primitives — Squads on Solana, Safe with the Allowance Module on EVM chains. There is nothing new for you to trust.

Which tokens can an agent spend?

The chain's dollar only — USDC or USDG. Amounts are exact to a millionth of a dollar and never rounded; a value that would need rounding is refused instead.

Does the agent's explanation affect the decision?

Never. It is shown to you and marked unverified. Decisions use only your policy and the simulated effect of the transaction. An agent that lies about what it is doing changes nothing.

What happens if I do not answer an approval?

Nothing is paid. Approvals expire after ten minutes and the default is always no. Silence costs you a missed payment, never money.
